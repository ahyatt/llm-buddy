#+title: llm-buddy

llm-buddy is an Emacs package that watches your recent buffer edits and asks an
LLM to review them.  When it finds something worth pointing out, it can add a
short inline note in the relevant buffer.

The goal is lightweight feedback while you work: typos, logic mistakes,
questionable edits, or prose issues that a normal compiler, linter, or spell
checker may not catch.  It also can make fixes as it finds smaller problems, if
configured to do so.

* How it works

llm-buddy records changes in tracked buffers, groups nearby edits together, and
formats the net change as a numbered unified diff.  On idle, or when you call
~llm-buddy-advice~, it sends that diff to the configured provider from the
~llm~ package.

Inline note overlays stay visible while you edit.  Changes anywhere in the
review scope queue active notes for review after idle time, so corrections
outside the annotated line can also remove obsolete notes.  Uncertain note
decisions can use chat review, even when the diff is clean.  Before new feedback
is allowed, that chat can only update or remove existing notes.  Notes can also
be dismissed manually with ~llm-buddy-dismiss-note~ and ~llm-buddy-dismiss-notes~.

When ~llm-buddy-decision-provider~ is set to a decision model (see the [[https://github.com/ahyatt/llm#decisions][LLM readme]]
for what this means), this quick and cheap model is used to check the buffer
more often for issues, and can clear obsolete notes much more quickly.  In this
mode, existing notes are checked after half a second of idle time, controlled by
~llm-buddy-decision-idle-delay~.  New suggestions and automatic fixes wait for
~llm-buddy-feedback-idle-delay~ (default three seconds idle); regular checks are
at least ~llm-buddy-decision-interval~ seconds apart (default five).  The same
decision call asks whether editing is finished, classifies errors, and checks
existing notes for corrections.  New feedback requires a =finished= answer with at
least 0.8 confidence.  Unfinished, uncertain, missing, or failed editing
decisions defer new feedback and leave the changes pending for a later check.
Balanced parentheses alone do not establish that editing is finished.

To allow new notes and fixes, pause on a blank line after the function or
paragraph you are editing.  Resuming edits defers feedback; corrected notes
can disappear while you continue working.

* Setup

Load the package and configure an ~llm~ provider:

#+begin_src emacs-lisp
(add-to-list 'load-path "~/src/llm-buddy")
(require 'llm-buddy)
(require 'llm-openai)

;; Example only: set this to whatever provider object your llm setup uses, and
;; use a real key.
(setq llm-buddy-provider (make-llm-openai :chat-model "gpt-6-luna" :key my-openai-key))
;; Optional fast classifier, for example a TypeSafe decision provider:
;; (require 'llm-typesafe)
;; (setq llm-buddy-decision-provider (make-llm-typesafe :key my-typsafe-key))
#+end_src

For details on setting up providers, see [[https://github.com/ahyatt/llm][the LLM package]].  The LLM package supports most major providers, including local ones.

Then enable automatic review:

#+begin_src emacs-lisp
(llm-buddy-global-mode 1)
#+end_src

You can also run one review manually:

#+begin_src emacs-lisp
(llm-buddy-advice)
#+end_src

* Configuring noted problem severity, and fixes
Detected problems are assigned a severity, one of =trivial=, =significant= or =critical=.  You can set the minimum severity that will get a note by configuring ~llm-buddy-detect-minimum~, setting it to one of the symbols.  By default, it is set to =significant=, which should mean that problems are noted that affect whatever you are trying to do, whereas setting it to =trivial= may get typos and whitespace issues flagged as well.

Problems that are below the ~llm-buddy-detect-minimum~ value can be fixed by setting ~llm-buddy-fix-unreported~ to a non-=nil= value.  If possible, the LLM will attempt to fix issues.  These fixes happen in the background when the user is idle for ~llm-buddy-fix-idle-delay~ seconds (default =3= seconds), without interrupting editing.  There are a variety of reasons why the fix may not happen, such as the text being changed after the problem detection.  Think of these fixes as something that might happen but aren't guaranteed to happen.

* Main commands

- ~llm-buddy-global-mode~ enables or disables global tracking and idle review.
- ~llm-buddy-advice~ reviews the current scope's recent changes now.
- ~llm-buddy-clear-history~ clears recorded change history.
- ~llm-buddy-dismiss-note~ dismisses the llm-buddy note on the current line.
- ~llm-buddy-dismiss-notes~ dismisses all visible llm-buddy notes.

Useful options:

- ~llm-buddy-provider~ is the provider used for advice.
- ~llm-buddy-decision-provider~ enables fast diff and note decisions.
- ~llm-buddy-decision-clean-confidence~ sets how certain quick checks must be to skip a full review.
- ~llm-buddy-tracked-modes~ controls which major modes are watched.
- ~llm-buddy-coalesce-window~ controls how nearby edits are merged.
- ~llm-buddy-auto-interval~ controls the minimum time between automatic runs.
- ~llm-buddy-auto-idle-delay~ controls how long Emacs must be idle first.
- ~llm-buddy-max-iterations~ bounds the tool-use loop for one review.

* Quality and benchmarks

~llm-buddy-quality.el~ helps capture and judge real advice runs.  Enable
~llm-buddy-debug-mode~, run ~llm-buddy-advice~, then call ~llm-buddy-judge~ to
mark the captured diff as clean or as requiring expected warnings.  Saved cases
are written under ~quality/~.  This code is a work in progress.

~llm-buddy-benchmark.el~ contains a small benchmark suite that measures review
quality with precision, recall, and F1:

#+begin_src emacs-lisp
(require 'llm-buddy-benchmark)
(llm-buddy-benchmark-run)
#+end_src

Reports can be displayed in Emacs or written to Markdown and HTML:

#+begin_src emacs-lisp
(llm-buddy-benchmark-report)
(llm-buddy-benchmark-write-report)
(llm-buddy-benchmark-write-html)
#+end_src

* Why not a flycheck backend?

The purpose of this package is to provide a commentary on new text added, not pre-existing text.  =flycheck= and =flymake= both check the entire buffer or file for issues, while =llm-buddy= only checks changed items.  It also supports dismissing notes.
